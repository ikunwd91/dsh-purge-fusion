# purge-re-deep-dive —— 静态深挖

前置：已完成 `purge-re-triage`，拿到 sha256 与架构。

## 1. 建立可导航的骨架

按顺序做，每步都记录地址（64 位一律十六进制字符串）：

1. **入口链**：文件入口 → CRT 初始化 → 真实 `main`/`DllMain`。壳或保护常在入口做跳板。
2. **函数边界**：从入口递归跟随 `call`/`jmp`，配合 `.pdata`（PE x64）或 `.eh_frame`（ELF）补边界。
3. **调用图**：出度高的函数是分发器；入度高的函数是公共工具（解密、校验、日志）。
4. **交叉引用**：对关键字符串/常量做 xref，反向定位使用点——这是最快到达业务逻辑的路径。

## 2. 单函数分析模板

```
目标: NAME @ 0xADDR (RVA 0xRVA, 文件偏移 0xOFF)
入参: 寄存器/栈布局，调用约定
出参: 返回值含义，是否写内存
控制流: 分支数、循环、switch 表位置
常量: 魔数/掩码/S-Box/表地址
调用: 调用了谁，传了什么
结论: 该函数做什么 + 证据地址
```

- 地址空间不混用：静态 VA / RVA / 文件偏移 / 运行时 VA / 栈 / 寄存器分开写。转换只在明确 image base、已加载模块和文件映射时做，BSS 不伪造文件偏移。
- 反编译器输出与反汇编冲突时，以反汇编为准，并记录差异（常见于被手工改过的分支、非标准栈帧）。

## 3. 常见结构识别

- **switch**：跳转表 + 边界检查（`cmp reg, N` + `jmp [table+reg*8]`）；表项可能被加密或重定位。
- **虚表 / RTTI**：MSVC 的 `??_7` 符号、Itanium 的 `_ZTV`；虚槽要显式 table+offset，不能靠名字猜。
- **结构体**：按访问偏移聚类（`[reg+0x18]` 出现处），先定字段宽度再定类型。
- **字符串解密**：定位解密函数 → 找调用点 → 用常量/密钥还原明文；还原后必须与另一条独立证据（配置样本、协议报文）交叉核对。

## 4. 去混淆与平坦化

- 先判断混淆类型：指令替换（MBA）、控制流平坦化（状态机 dispatcher）、不透明谓词、字符串加密、导入隐藏。
- 平坦化识别特征：一个高入度 dispatcher + 全局状态变量 + 每个真实块末尾回写状态。
- 处理顺序：恢复块归属 → 简化状态变量 → 折叠不透明谓词 → 再谈指令级等价。
- 只做**有界**改写：每次改写保留原字节、改写前后对照、命中规则计数。规则没命中就写 `rule_hits=0`，不要声称已去平坦化。

## 5. 证据分级（写报告时照抄）

| 级别 | 含义 |
|---|---|
| E0 | 静态观察：字节、字符串、导入、结构字段 |
| E1 | 静态推导：控制流/数据流可复现路径，地址可点 |
| E2 | 动态观测：真实执行到的寄存器/内存/返回值 |
| E3 | 业务确认：与外部独立证据（协议、配置、日志）一致 |

低级别不能冒充高级别。反编译「看起来对」只是 E1。
