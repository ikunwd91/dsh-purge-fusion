# purge-re-crypto-protocol —— 解密与协议

## 1. 解密：先定位，再验证

定位顺序（成本从低到高）：

1. **常量特征**：AES S-Box（`63 7C 77 7B`）、MD5/SHA 初始常量、CRC 表、Base64 字母表、自定义置换表。
2. **导入/符号**：`CryptEncrypt/CryptDecrypt`、`BCrypt*`、`EVP_*`、`mbedtls_*`。
3. **调用上下文**：找「读配置 → 调函数 → 写明文」的链，密钥常来自同级参数或全局结构体字段。
4. **数据侧**：密文长度对齐（16/8 字节）、块间重复、IV 前缀、tag 后缀。

记录：算法候选、模式（ECB/CBC/CTR/GCM）、key/IV/tag/AAD 来源地址、padding 方式。**没看到的参数不许猜默认值。**

## 2. 有界恢复（XOR / 候选检索）

- 单字节 XOR：用已知明文 crib 或字符频率打分，候选按分数排序，**必须用独立明文验证**。
- 重复 XOR：先求密钥长度（Kasiski / 汉明距离），再逐列解。
- AES 候选材料：只在已有候选 key 材料（配置、字符串、栈值）范围内检索，不做全空间穷举。
- 部分密钥（unknown mask）不得当完整密钥使用。

## 3. 验证口径

| 状态 | 条件 |
|---|---|
| `verified` | 与独立 expected 明文逐字节一致，或 GCM tag 认证通过 |
| `candidate` | 统计/crib/padding 合理，但没有独立验证 |
| `not-requested` | 没给 expected，也没做认证 |

密钥/IV/tag 不进报告正文，只写引用（ref）与来源地址。

## 4. 协议还原

1. **取样本**：至少两条同类型交互（请求+响应），记录方向、时序、缺口。
2. **定 framing**：定长 / 长度前缀（含长度字段自身宽度与字节序）/ 分隔符 / 魔数+长度+类型。
3. **切字段**：按候选边界切，标注每个字段的字节范围、取值分布、是否随会话变化。
4. **训练/保留分离**：用一半样本推断、另一半验证；推断不成立的规则要写 `ambiguous`，不能强行套。
5. **状态建模**：把交互序列抽象为状态（握手 → 认证 → 业务 → 心跳），标出触发条件与超时。状态机只接受有限域内的等价合并，合并要写清合并依据。

## 5. 常见坑

- 只看到压缩头就断言「完整压缩载荷」——必须解压成功且长度/校验一致。
- 把加密的 base64 当明文解，得到「看起来像 JSON」的乱码——要用结构校验（括号配对、字段名白名单）。
- 把 checksum 当加密：先试 CRC16/CRC32/Adler32/FNV 再谈密码学。
- 抓包里有 TLS：先确认是否有 pinning；有 pinning 时静态定位校验函数比硬打补丁更稳。

## 6. 交付

- 算法/模式/参数来源、验证状态、样本 sha256 与字节范围。
- 协议：framing 图、字段表、状态机、哪些结论有 holdout 支持。
- 未做项：未执行的解密函数、未覆盖的报文类型、未验证的 checksum。
